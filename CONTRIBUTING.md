# Contributing to AyitiDev

- 🇺🇸 English (default)
- 🇭🇹 [Kreyòl Ayisyen](CONTRIBUTING.ht.md)

First off, thank you for taking the time to contribute! 🎉

AyitiDev is an open-source community dedicated to building, sharing, and supporting technology that benefits Haiti, the Haitian diaspora, and the global developer community.

Whether you're fixing a typo, improving documentation, reporting a bug, reviewing a pull request, or writing code, every contribution matters.

«If you enjoy a project but don't have time to contribute, you can still support us by:

- ⭐ Starring the repository
- 📢 Sharing it with others
- 💬 Recommending it to friends or colleagues
- ❤️ Using and providing feedback on our projects»

## Code of Conduct

By participating in any AyitiDev project, you agree to follow our "Code of Conduct" (CODE_OF_CONDUCT.md).

Please be respectful, constructive, and welcoming to contributors of all experience levels.

---

## Ways to Contribute

There are many ways to contribute:

- Report bugs
- Suggest new features
- Improve documentation
- Fix typos
- Write or improve code
- Add tests
- Review pull requests
- Answer questions from other contributors

Don't worry if you're new to open source. Many repositories include issues labeled "good first issue" to help you get started.

---

## Reporting Bugs

Before opening a bug report:

- Make sure you're using the latest version of the project.
- Search existing issues to avoid duplicates.
- Verify the issue can be reproduced.

When creating a bug report, please include:

- A clear description of the problem
- Steps to reproduce it
- Expected behavior
- Actual behavior
- Relevant environment information (OS, language/runtime version, etc.)
- Screenshots or logs if applicable

«Security issues should never be reported publicly. If a repository provides security contact information, please use that instead of opening a public issue.»

---

## Suggesting Enhancements

Feature requests are always welcome.

When opening an enhancement request:

- Use a clear and descriptive title.
- Explain the problem you're trying to solve.
- Describe your proposed solution.
- Include examples or mockups if they help explain the idea.

Please search existing issues before creating a new one.

---

## Submitting Pull Requests

Before submitting a pull request:

- Fork the repository.
- Create a new branch for your changes.
- Keep pull requests focused on a single change whenever possible.
- Test your changes if applicable.
- Update documentation when needed.

Pull requests should include:

- A clear description of the changes
- The motivation behind them
- References to related issues, if applicable

Please be open to feedback during code review. Reviews are part of collaboration, not criticism.

---

## Commit Messages

Write clear and meaningful commit messages.

Good examples:

- "fix: handle empty input"
- "docs: add installation instructions"
- "feat: add Haitian Creole tokenizer"
- "refactor: simplify parser logic"

Avoid messages like:

- "update"
- "fix"
- "changes"
